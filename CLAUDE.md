# Правила работы с магазином tl-shop.com.ua (Horoshop MCP, store `tlshop`)

## После любого `horoshop_admin_record_save` по товару — сверять `alt_parent`

Сохранение формы товара в админке (`horoshop_admin_record_save`, entity `products`) может срезать дополнительные разделы: форма показывает поле `parent_common[alt_parent][]` только с одним значением и при сохранении записывает его обратно. Так 13.10.2026 у 05006634001 пропал раздел 1230 из двух (1230 + 1267).

Порядок:
1. Перед `record_save` снять `horoshop_catalog_export` товара (минимум `article`, `alt_parent`, `parent`).
2. Сразу после сохранения снова выгрузить и сравнить `alt_parent` (и `parent`) с выгрузкой «до».
3. Если разделы пропали — восстановить через `horoshop_catalog_import` с полным списком `alt_parent: [{id}, ...]` (dryRun → запись), затем снова сверить выгрузкой.

По возможности писать поля товара через `horoshop_catalog_import`, а `record_save` использовать только для того, чего в импорте нет (alt фото, артикул модификации и т. п.).

**Сохранение карточки владельцем в админке (тест 25.10.2026, 05136032001):** визуальный редактор НЕ срезает блок состава (`<details>`/`<summary>`/`<style>`/сетка/значки — структура та же; он лишь переписывает сущности, CRLF, порядок атрибутов, `loading="lazy"`, `type="text/css"` — сравнивать `vt/html_same.js`, не строкой), характеристики с множественным выбором и доп. разделы не трогает. Писатели, которые требуют «описание на сайте = старое», после такого сохранения пропустят товар — сравнивать через `html_same`.

**То же с характеристиками (24.10.2026).** Любое сохранение формы товара — и `horoshop_admin_upload_image` в слот фото (он сохраняет форму) — срезает значения характеристик с множественным выбором (05018264001: из двух «Особливості викрутки» осталось одно; при замене 506 главных фото — у 77 товаров, `alt_parent` — у 2). Сверять ВСЮ выгрузку (характеристики, `alt_parent`, описание, SEO …) до / после и возвращать срезанное импортом — так делает `photos_audit/main_replace.js` (`restore`); замена главного фото — в тот же слот (первый file field формы = `images[0]`).

## Название товара — всегда в ОБА поля: `title` и `mod_title` (UA/RU)

У товара два названия: `title` (общее) и `mod_title` (название модификации). Витрина (h1, `<title>` по шаблону) и список товаров в админке показывают `mod_title`; импорт только `title` на сайте не виден (17.10.2026: 2008 названий записались в `title`, витрина осталась старой — дописывали `mod_title`).

- Любая запись названия (`horoshop_catalog_import`) — `title: {ua, ru}` и `mod_title: {ua, ru}` с одинаковым текстом; dryRun допускает только `title.*` и `mod_title.*`; сверка выгрузкой — оба поля (в `includedParams` добавить `mod_title`).
- Новые товары: `run_batch` (`lib/build.js` `payloadNew`) пишет оба поля. Скрипты названий (`tools/names/write.js`, `lib/ipr_fix.js`) — тоже.
- Проверка на витрине: h1 страницы UA и `/ru/` = новое название.

## Фильтры каталога

Эталон подхода для всех групп товаров (пилот — «Біти», раздел 1062, 15–16.10.2026).

- Для КАЖДОЙ группы набор фильтров подбирается заново — по реальным данным этой группы и по тому, как покупатель выбирает именно этот инструмент. Фильтры бит — пример, а не шаблон для копирования.
- Существующую характеристику переиспользовать ТОЛЬКО при том же смысле и том же формате значений (например, «Профіль»: PH/PZ/TX/HEX — у бит и викруток одно и то же). Иначе — отдельная характеристика группы. Характеристики бит («Тип біти», «Хвостовик», «Особливості» бит) в другие группы не переносить.
- Характеристики — в общем шаблоне 460, тип «список», множественный выбор (включить потом нельзя — Horoshop сбрасывает значения), справочник на каждую, значения UA/RU. Значения нормализованы и упорядочены по возрастанию (не по алфавиту), список полный — из реальных данных группы.
- Порядок значений в справочнике = порядок создания: перед импортом одним «посевом» создать все значения в нужном порядке, затем полный импорт (у посевного товара пустые поля очищаются явно). RU значений — `horoshop_admin_dictionary_value_set`, RU заголовков — `horoshop_admin_interface_translation_set`.
- Значения — ТОЛЬКО из даташитов WERA, таблиц серий и названий; ничего не додумывать. Если значение неоднозначно — НЕ записывать, товар в список «спорные» (`inventory\filters_<группа>_disputed.xlsx`).
- **ПРИНЦИП (владелец 22.10.2026, вместо «строгого правила полноты»).** Значение у товара реально есть (паспорт WERA / wera.de, у товара без паспорта — описание на сайте) → записать, чтобы товар находился в фильтре (712 i VDE — 154 мм, Joker 11 Set — размеры, Г-ключи — размеры с wera.de). Свойства по смыслу нет (у ручки нет жала, у обычной ручки нет момента, у «Викрутка з набором біт» нет длины стрижня, у принадлежности нет размера, у тріскачки нет размера наконечника) → не придумывать; что такой товар пропадает при выборе фильтра — нормально (как с «Особливостями»). Фильтр, где у всех товаров раздела одно и то же значение, не ставится — КРОМЕ «Довжина…» в мм; признак («Особливості…», «… у складі», «Тип біт у наборі») — и у 1 товара раздела (владелец 22.10.2026 (i)); убирается только фильтр, где у ВСЕХ товаров одно и то же значение (кроме «Довжина…» в мм). Фильтр не убирается только потому, что у принадлежности / ручки нет значения.
- Полнота: каждый товар раздела (основной и `alt_parent`) получает значение в каждой обязательной характеристике группы, кроме спорных (они в отчёт). **Принадлежности не получают размеров** (владелец 21.10.2026; раньше — «все значения раздела»): ручки-тримачі, знімачі, держатели, підставки, сумки — без «Профіль і розмір», «Профіль», «Розмір…», «… у складі»; остальные характеристики (вид, длина, ESD, магнит, кольцо …) — по паспорту, только однозначное. Пробел — это отсутствие значения в основном фильтре (вид, профиль / размер, длина, привод); набор без PZ в «PZ у складі» и инструмент без магнита в «Особливостях» — не пробел. Не пробел по правилу (владелец 22.10.2026, `fill_audit` пишет их отдельно с причиной — `cat/fill_audit_skipped.json`): «… у складі» у набора без винтовых профилей (только торцеві головки / торцеві викрутки / тріскачки — по записанному «Профіль» / «Профіль і розмір», без профиля — по составу); «Діапазон моменту» / «Налаштування моменту» / «Особливості динамометра» у не динамометрического инструмента (обычная ручка); любая длина у принадлежности (ручка-тримач — жала нет); перехідник 712 i VDE (05006642001, 05073702001) с 22.10.2026 (h) — вид «Перехідник» и «Довжина робочого кінця» 154 мм (паспорт «1/4" x 154 мм», `vde.js`); тріскачка — размера наконечника нет; 05135826001 Christmas MIX — один набор из витрины (932 A, 350 PH, 160 iS VDE), размеров и длин у WERA нет, название и вид не менять. 05133126001 — не трогать, ждёт владельца. «Привід» у обычных ручек-тримачів Kompakt VDE (раздел 1231) = «Kraftform Kompakt VDE (вставки)», как у динамометрических (паспорт: «исключительно для сменных отверток VDE»; `vde.js`, 22.10.2026). Проверка — `node cat/fill_audit.js <live.json>` (группы «Викрутки», Kompakt, «Діелектричні»; фильтры раздела = витрина ∪ план админки).
- НАБОРЫ: набор получает ВСЕ значения по своему составу — все профили (PH, PZ, TX, SL, HEX…), все размеры наконечников/головок/ключей, привод и т. д. — по каждой характеристике группы, которая имеет смысл для набора. Источник — состав набора из даташита WERA (`lib/ds_set.mjs`), название — только подсказка. Состав в даташите не найден — набор в спорные, не придумывать. Цель: покупатель в разделе наборов отмечает PH и PZ и видит наборы, где они есть.
- Состав набора раскрывается до конечных позиций: компонент-набор (вложенный набор, ложемент в визке) открывается по его даташиту (`tools/cat/comp_expand.js`). Принадлежности в составе (ручки, держатели, липучки, футляры) значений не дают. С 22.10.2026 (h) вложенный набор раскрывает и `cat/sets_fill.js` (через `comp_expand`: Tool-Check Modular Set 1 → Modular 1 → головки 8790 HMA); знімач, как и другие принадлежности, значений набору не даёт. Паспорт читается ЦЕЛИКОМ: `lib/dstext.mjs` (тексты `batch/ds/*.txt`) — все страницы (до 22.10.2026 только 1–2; `cat/ds_retext.mjs` пересобрал 2448 текстов, старые — `backup/ds_txt_1022/`), `lib/ds_set.mjs` / `cat/ds_comp_all.json` / `cat/sets_comp.json` — все страницы; `cat/1185_sets.json` (Joker) пересобран из `ds_comp_all`. Состав, которого нет в паспорте WERA, — `cat/comp_extra.js` (источник в каждой группе; `node cat/comp_extra.js` вносит в кэши составов): TL105 — по описанию товара на сайте. Размеры наборов Г-ключей без состава в паспорте — с wera.de (`WERA_DE` / `FIX_SIZES` в `pr_size.js`; `g_lkeys.js` берёт оттуда и «Розмір ключа»). Рождественские витрины 05135825001 (Hex-Plus) и 05135824001 (Bit-Check 30) — продаётся ОДНА карта / один набор (как Christmas MIX): название и вид не менять, значения по одной карте (Hex-Plus: 3,0; 4,0; 5,0; 6,0 — паспорт; «Кулькова головка» — wera.de «Kugelkopf», 22.10 (i)), у Bit-Check 30 размеров у WERA нет. «Покриття» Г-ключей: WERA (паспорт / wera.de) называет два покрытия — ставятся оба (967/9 TX XL HF 1 05024450001, 967/9 TX XL 1 05024460001 — BlackLaser + Цинкове фосфатування, `lkeys.js`, 22.10 (i)). Wera 2go E 1 / H 1 — «Профіль», «Нержавіюча сталь» / «З індикатором напруги» по составу вложенных наборов (Zyklop Speed, Kompakt Turbo i, Kompakt H 1 с тестером 247; генератор `kk.js`, 22.10 (i)). 05133126001 — не трогать.
- Состав читать ПОЛНОСТЬЮ, не только строки с артикулом из каталога: строки без артикула или с артикулом, которого нет в каталоге (комбинированные концы «PH 1 x PH 2», Г-ключи 950 L, головки-биты 8740 B — `fromText` в `sets_fill.js` с 22.10.2026 (i) читает 8740 как HEX, а длину головки Zyklop пишет в «Довжина головки»: Bicycle Set 8 — 100 / 107 мм; Bicycle Set 7 05004175001 — 8740 B «8 mm x 100 мм», «10 mm x 100 мм» (паспорт стр. 4): «Довжина головки» 100 мм, HEX 8,0 / 10,0 в «HEX у складі» и «Профіль і розмір» — `FIX_SIZES` в `pr_size.js`, записано 23.10.2026), и состав, описанный в даташите только текстом («Отвертка 350 PH…», «биты для винтов Phillips, Pozidriv и TORX®»), тоже дают профили и размеры. Такие наборы — в `tools/cat/sets_fix.js` (значения + цитата из даташита; пишет только добавлением), `g_sklad.js` их учитывает. Количество без состава («3 предмета») — не источник.
- Компонент — именованный набор WERA без артикула, под который подходит больше одного набора каталога («Tool-Check PLUS, 39 предметов») → спорные, не угадывать.
- Набор вне групп фильтров (например 1056 «Інструменти для велосипедів») тоже получает «… у складі» и «Профіль» по составу.
- Аудит после любых изменений наборов: полная выгрузка (`node lib/full_export.js <out.json> article,title,parent,alt_parent,display_in_showcase,characteristics,link`) → `node cat/sets_audit.js <out.json> pages` → `inventory\sets_audit.xlsx`: наборы без «… у складі» с причиной, без характеристик, что показывает карточка по каждому разделу наборов.
- Карточка: «… у складі» скрыты только если на разделе группы задан явный список «Характеристики для страницы товара». Через MCP список не читается и не пишется — настраивает владелец по инструкции (`docs/sets_card_checklist.md`); проверка — `sets_audit.js … pages`. 19.10.2026 списков нет ни на одном разделе наборов (карточки показывают все характеристики, включая «… у складі»), кроме 1055 и 1056 — там только «Бренд».
- «… у складі» (логика И для наборов): внутри одного фильтра значения Хорошопа работают как ИЛИ (Профіль PH + PZ = наборы с PH ИЛИ PZ), разные фильтры — как И. Поэтому у КАЖДОГО набора есть характеристики так/ні «PH у складі», «PZ у складі», «TX у складі», «SL у складі», «HEX у складі», «Квадрат у складі», «TX BO у складі», «PlusMinus у складі» (только профили, которые есть в ≥ 20 наборах). С 19.10.2026 значение — не «Так», а РАЗМЕРЫ этого профиля в составе, в формате «Профіль і розмір» («PH 1», «PH 2»; «SL 0,6×3,5»; «TX BO 20»; «PZ/S 1»), по возрастанию: тогда «PH 1» в одном фильтре + «PZ 2» в другом = набор, где есть и то и другое. Биты BO засчитываются и в «TX у складі» / «HEX у складі» («TX 20»), и в «TX BO у складі» («TX BO 20»). Профиль есть, а размеров нет ни в даташите, ни на странице набора на wera.de (блок «Werkzeuge in diesem Set») — значение «PH (розмір не вказано)» (RU «… (размер не указан)»), последним в списке, набор в спорные. Источник — состав (как выше) и «Профіль» набора; записанные значения — `tools/cat/pr_size_values.json`, расчёт новых — `skladValues` в `tools/cat/pr_size.js`. Группа `tools/cat/g_sklad.js`, пишет только наборы; новые наборы — добавить туда же. В разделах наборов эти фильтры стоят вместо «Профіль» (свой список фильтров у подраздела), на странице товара их НЕ показывать (явный список «Характеристики для страницы товара» на разделе группы).
- 1055 «Інструментальний візок та ложементи» — как наборы: «Вид інструменту» (Ложемент / Інструментальний візок), «Комплектація» (З інструментом / Без інструменту), «Інструмент у ложементі» (по составу; у пустого ложемента — по заполненному набору WERA, где он в составе или с тем же названием в даташите), «Профіль», «Привід», «… у складі». Группа `tools/cat/g_trolley.js`.
- «Профіль і розмір» (`rozmir_nakonechnyka`, param 6600, справочник 392; до 19.10.2026 — «Розмір наконечника», RU «Профиль и размер»): одно значение = профиль + размер, короткий формат — «PH 0», «PH 2», «PZ 1», «PZ/S 2», «TX 20», «IP 5», «IPR 1», «SL 1,0×5,5» (толщина×ширина, как в даташите), «HEX 5,0», «HEX 3/16″», «Квадрат #2», «Торцева 7 мм» (RU «Торцевая 7 мм»), «TRI-WING® 2», «Microstix® m», «Pentalobe 1,4». Общая характеристика групп «Викрутки», Kraftform Kompakt, динамометрии и (с 21.10.2026) «Діелектричні інструменти» и Zyklop: у викруток и вставок VDE вместо «Розмір робочого кінця» (399), у наборов VDE — размеры их «… у складі»; 399 остаётся только там, где формата А нет (торцевые головки Zyklop VDE, XZN, шафовые вставки, ключи Joker VDE, торцевые размеры в наборах) — `tools/cat/night_vde.js`, `night_vde2.js`, генератор `g_vde.js`. Zyklop (решение владельца 21.10.2026): викруткові головки (TX, HEX, PH, PZ, SL, и Zyklop VDE) — «Профіль і розмір» («TX 20», «HEX 8,0») вместо «Розмір головки» / 399; «Розмір головки» — только торцевые головки («8 мм», «1/4″»); наборы Zyklop — «Профіль і розмір» = размеры их «… у складі», голые размеры головок из «Розмір головки» убраны (22.10.2026 (i) — и дюймовые у наборов викруткових головок под шестигранник 05003884001, 05003974001, 05003181001: «HEX 5/64″ …» уже стояли в 392); XZN — как есть (`tools/cat/zyk_pr.js`, генератор `g_zyklop.js`). Размер, которого нет в справочнике 392 (HEX 9,0 / 14,0 / 17,0 / 19,0, TX 60), не создавать без решения владельца — новое значение встанет в конец списка фильтра; раздел головок с таким размером остаётся на «Розмір головки» целиком (не делить фильтр раздела). Порядок справочника: PH, PZ, PH/S·PZ/S, TX, IP, IPR, SL, HEX, Квадрат, Торцева, TRI-WING®, TORQ-SET®, Spanner, Microstix®, Pentalobe; внутри — по возрастанию (SL — по ширине, затем толщине). Пары — `tools/cat/pr_size.js`: одиночный инструмент — его профиль и размер, сверка с первой строкой даташита (даташит главнее), толщина шлица из таблицы серии / даташита / названия; набор — по составу WERA. Записанное — `tools/cat/pr_size_values.json` (источник для `g_vykrutky`, `g_kk`, `g_dyn`, `g_sklad`; новые товары считаются функциями `tipValues` / `skladValues`). В списке значений справочника в админке позиция значения переполняется после id 255 (значения 256+ встают в начало списка), на витрине порядок верный — по id.
